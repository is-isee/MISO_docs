Fortran Correspondence Table

This table is for looking up how to write in C++ and MISO what you used to write in Fortran. Find the Fortran form in the left column, then go to the form in the right column and to the chapter that explains it. The correspondences are between “forms used for the same purpose”, so the meanings are not always exactly the same. Rows with differences carry a note. Source paths are relative to the folder where you cloned MISO.

5.3 Memory layout

In Fortran, the first index is contiguous (column-major); in MISO’s Array3D, the last index is contiguous (row-major). Even when you write the same a(i, j, k), the elements that are adjacent in memory are different.

Fortran a(i, j, k)

MISO a(i, j, k)

Adjacent element in memory

a(i+1, j, k)

a(i, j, k+1)

Loop to run fast (innermost)

i

k

Element position (a(nx, ny, nz))

i + nx*(j + ny*k) (converted to 0-based)

(i*ny + j)*nz + k

The following short program prints how far each element of a MISO Array3D is from the start of memory (an example for explanation).

// order.cpp: check the memory layout of Array3D
#include <iostream>

#include <miso/array3d.hpp>

int main() {
  miso::Array3D<double> a(2, 3, 4);  // a(i, j, k): i < 2, j < 3, k < 4
  const double *p = a.data();       // address of the first element
  // difference between an element's address and the first address = offset from the start
  std::cout << "a(0,0,1): " << &a(0, 0, 1) - p << "\n";
  std::cout << "a(0,1,0): " << &a(0, 1, 0) - p << "\n";
  std::cout << "a(1,0,0): " << &a(1, 0, 0) - p << "\n";
  std::cout << "a(1,2,3): " << &a(1, 2, 3) - p << "\n";
}

a(0,0,1): 1
a(0,1,0): 4
a(1,0,0): 12
a(1,2,3): 23

Increasing k by 1 moves to the adjacent element (1 away), increasing j by 1 moves 4 elements ahead, and increasing i by 1 moves \(3 \times 4 = 12\) elements ahead. If you create an array of the same size in Fortran, a(2, 3, 4), then a(2, 1, 1) is the second element from the start (1-based), and the i direction is contiguous. MISO output files (mhd/mhd.*.bin) are also written in this order, so be careful about the order of the indices when you read them in Fortran or NumPy.
