11. MISO の時間発展を読む

第 10 章 で書いた熱伝導の計算には、時間刻みの決定、右辺の差分、時間積分、境界の処理、出力という部品がありました。 MISO の MHD 計算も同じ部品でできています。この章では、デモの main() から始めて、1 ステップの中身と出力までを MISO のソースでたどり、方程式と差分式をコードに対応づけます。 最後に、自分で問題を作るときに書き換える場所を確かめます。

本文のパスは、MISO を clone したフォルダから辿ってください。GPU の章（第 9 章）を済ませていなくても、CPU 版のソースだけで読み進められます。CUDA 版は、CPU 版との対応だけを示します。

1. 基礎方程式と MISO の変数

1.2 基礎方程式

MISO は理想 MHD 方程式を、Gauss 単位系（磁場の項に \(1/4\pi\) が付く形）で解きます。 \(\partial_j\) は \(x, y, z\) 方向の偏微分、同じ添字 \(j\) が 2 回出たら \(j = x, y, z\) で和を取ります。 \(S_\rho\) などはソース項（外力や加熱）で、ユーザーが与えます（12 節）。

\[\begin{split} \begin{aligned} \frac{\partial \rho}{\partial t} &= -\partial_j(\rho v_j) + S_\rho, \\ \frac{\partial (\rho v_i)}{\partial t} &= -\partial_j(\rho v_i v_j) - \partial_i p - \partial_i\left(\frac{B^2}{8\pi}\right) + \frac{1}{4\pi}\partial_j(B_i B_j) + S_{v_i}, \\ \frac{\partial B_i}{\partial t} &= \partial_j(v_i B_j - v_j B_i) - \partial_i \phi + S_{B_i}, \\ \frac{\partial \phi}{\partial t} &= -c_h^2\, \partial_j B_j - \frac{\phi}{\tau}, \\ \frac{\partial E}{\partial t} &= -\partial_j\left[\left(\rho e + p + \frac{1}{2}\rho v^2 + \frac{B^2}{4\pi}\right) v_j - \frac{(\boldsymbol{v}\cdot\boldsymbol{B})}{4\pi} B_j\right] + S_E, \\ E &= \rho e + \frac{1}{2}\rho v^2 + \frac{B^2}{8\pi}. \end{aligned} \end{split}\]

磁場の式の \(-\partial_i\phi\) と \(\phi\) の式は、数値計算で生じる \(\nabla\cdot\boldsymbol{B}\) の誤差を波として運び出し（速さ \(c_h\)）、時間 \(\tau\) で減衰させる仕組みです。 この方法は双曲型の発散クリーニング（hyperbolic divergence cleaning）と呼ばれます（Dedner et al. 2002, J. Comput. Phys. 175, 645）。

1.3 状態方程式

圧力 \(p\) と音速 \(c_s\) は状態方程式（EOS: equation of state）から求めます。 MISO が用意している理想気体の EOS は miso/include/miso/eos.hpp の eos::IdealEOS です。比熱比を \(\gamma\)（設定の eos.gm）として、

\[ p = (\gamma - 1)\rho e, \qquad c_s = \sqrt{\gamma(\gamma - 1) e} = \sqrt{\gamma p/\rho} \]

を、gas_pressure と sound_speed の 2 つのメンバ関数で計算します。 どちらも for_each で全格子点を処理します（第 7 章）。

// miso/include/miso/eos.hpp の IdealEOS::gas_pressure（抜粋）
template <typename Backend>
void gas_pressure(Backend btag, mhd::FieldsView<const Real> qq,
                  Array3DView<Real> pr) const {
  const Real gm_ = gm;  // device lambdas must not capture `this`
  Range1D range{0, qq.size()};
  for_each(
      btag, range,
      MISO_LAMBDA(int i) { pr[i] = (gm_ - Real(1)) * qq.ro[i] * qq.ei[i]; });
}

メンバ変数 gm をローカル変数 gm_ に写してからラムダで使うのは、第 9 章 で説明した this キャプチャを避けるためです。

3.2 既定値と merge_yaml

すべてのキーを毎回書かなくてよいように、MISO は既定値を miso/include/miso/config_defaults.hpp に YAML の文字列として持っています。

// miso/include/miso/config_defaults.hpp（抜粋。コメントの一部を省略）
inline constexpr const char *config_default_yaml = R"yaml(
io:
  enabled: true
  continue: true
  save_dir: data/
  ...
mhd:
    # CFL number for time-stepping
    cfl_number: 0.5
    artificial_viscosity:
        ep: 1.0
        fh: 1.0
        ...
    )yaml";

R"yaml( ... )yaml" は生文字列リテラル（raw string literal）です。R"区切り( から )区切り" までを、改行や " も含めてそのまま 1 つの文字列にします。 YAML をそのまま C++ のソースに埋め込むために使っています。

miso/include/miso/config.hpp の Config のコンストラクタは、次の順に処理します。

  1. ランク 0 だけがファイルを読み（YAML::LoadFile）、文字列にして MPI_Bcast で全ランクに配ります。

  2. 全ランクで既定値の文字列を読み（YAML::Load(config_default_yaml)）、merge_yaml でユーザーの設定に足します。

  3. io.save_dir を、設定ファイルのあるフォルダからの相対パスとして解釈し、出力先を作ります。

// miso/include/miso/config.hpp
inline void merge_yaml(YAML::Node &target, const YAML::Node &defaults) {
  if (!defaults.IsMap()) {
    return;
  }

  if (!target || !target.IsMap()) {
    target = YAML::Node(YAML::NodeType::Map);
  }

  for (const auto &it : defaults) {
    const std::string key = it.first.as<std::string>();
    const YAML::Node &default_value = it.second;

    if (default_value.IsMap()) {
      YAML::Node child = target[key];
      merge_yaml(child, default_value);  // 入れ子のセクションは再帰的に補う
      target[key] = child;
    } else {
      if (!target[key]) {               // ユーザーが書いていないキーだけ補う
        target[key] = default_value;
      }
    }
  }
}

（merge_yaml の 2 つのコメントは説明のために足しました。） ユーザーが書いた値は上書きされず、書いていないキーだけが既定値で埋まります。セクションの中のセクション（mhd.artificial_viscosity など）も、キーごとに補われます。 補った結果は、出力先に config.yaml として保存されます（11 節）。実際に使われた値は、この保存されたファイルで確かめられます。

4.2 run()：時間ループ

// miso/include/miso/mhd_model_base.hpp（抜粋）
void run() {
  // Ensure to call methods in the derived class
  auto &d = derived();

  // Assert that d has eos, ic, bc, and src as member variables.
  static_assert(has_eos<Derived>::value,
                "Derived must have member variable 'eos'.");
  ...
  mhd.apply_initial_condition(d.ic, d.bc);
  if (config["io"]["continue"].template as<bool>() &&
      fs::exists(time.n_output_filepath())) {
    load_state();
  }

  save_metadata();
  save_if_needed();

  while (time.time < time.tend) {
    d.update();
    save_if_needed();
  }
}

処理

内容

derived()

static_cast<Derived &>(*this) で、自分を派生クラス Model として扱います（第 5 章）

static_assert(has_eos<Derived>::value, ...)

Model に eos などのメンバがなければ、コンパイル時にエラーにします（第 6 章）

mhd.apply_initial_condition(d.ic, d.bc)

CPU 上の一時配列に ic.apply で初期値を入れ、計算場所の qq へ写し、境界条件とハロー交換を 1 回行います

load_state()

io.continue が真で、前回の出力が残っていれば、最新の出力から再開します（11 節）

save_metadata()

設定（既定値を補ったもの）、格子、MPI の配置を書き出します

save_if_needed()

出力する時刻に達していれば状態を書き出します

d.update()

1 ステップ進めます

config["io"]["continue"].template as<bool>() の .template は、テンプレートの中で、依存する型のメンバテンプレートを呼ぶときに必要な書き方です。as<bool>() と同じ意味に読んで構いません。

d.update() は、Model が update() を定義していればそれを呼び、なければ基底の ModelBase::update() を呼びます。 demo/mhd3d_magnetosphere/src/main.cpp の Model は自分の update() を定義し、時間刻みの決め方を変えています。

4.3 update()：1 ステップの入口

// miso/include/miso/mhd_model_base.hpp（抜粋）
void update() {
  auto &d = derived();
  using Source = decltype(d.src);
  ...
  auto dt = mhd.cfl(d.eos);
  if constexpr (has_dt_limit<Source>::value) {
    // dt_limit() returns the limit of this rank: take the global minimum.
    ...
    Real dt_src = static_cast<Real>(d.src.dt_limit());
    ...
    MPI_Allreduce(&dt_src, &dt_src_g, 1, mpi::data_type<Real>(), MPI_MIN,
                  mpi::comm());
    ...
    dt = std::min(dt, dt_src_g);
  }
  mhd.update(dt, d.eos, d.bc, d.src);
  time.update(dt);
}

  1. mhd.cfl(d.eos) で CFL 条件から時間刻みを決めます（6 節）。

  2. ソース項が dt_limit() を持っていれば、その制限（全ランクの最小値）も合わせます。持っていなければ if constexpr の中はコンパイルされません。

  3. mhd.update で状態を 1 ステップ進めます（5 節）。

  4. time.update(dt) で時刻とステップ数を進めます。

5. 1 ステップの流れ

MHD::update から呼ばれる Integrator::update が、1 ステップの本体です。 Integrator は miso/include/miso/mhd_integrator.hpp で宣言され、CPU 版と GPU 版が別々のファイルで特殊化されています（第 6 章）。

CPU 版の update は 3 行です。

// miso/include/miso/mhd_integrator_host.hpp

            const Source &src, Fields<Real, backend::Host> &qq) {
  divb_parameters_set(dt);
  runge_kutta_4step(dt, eos, bc, src, qq);
  apply_artificial_viscosity(dt, eos, bc, qq);

divb_parameters_set は、発散クリーニングの速さ \(c_h\) と減衰時間 \(\tau\) を、時間刻みに合わせて決めます。

// miso/include/miso/mhd_integrator_host.hpp
void divb_parameters_set(Real dt) {
  ch_divb = 0.8 * cfl_number * grid.min_dxyz / dt;
  ch_divb_square = ch_divb * ch_divb;
  tau_divb = 2.0 * dt;
}

6. CFL 条件による時間刻み

7. 4 段の Runge–Kutta 法

7.1 runge_kutta_4step

方程式を \(\partial q/\partial t = R(q)\) と書きます。\(q\) は保存量（\(\rho\), \(\rho\boldsymbol{v}\), \(\boldsymbol{B}\), \(\phi\), \(E\)）、\(R\) は右辺（空間微分とソース項）です。 MISO は、次の 4 段で \(q^n\) から \(q^{n+1}\) を作ります。

\[\begin{split} \begin{aligned} q^{(1)} &= q^n + \frac{\Delta t}{4} R(q^n), \\ q^{(2)} &= q^n + \frac{\Delta t}{3} R(q^{(1)}), \\ q^{(3)} &= q^n + \frac{\Delta t}{2} R(q^{(2)}), \\ q^{n+1} &= q^n + \Delta t\, R(q^{(3)}). \end{aligned} \end{split}\]

各段は「元の値 \(q^n\) に、直前の段の値で評価した右辺を足す」形です。必要な配列は、元の値、直前の段の値、結果の 3 組だけです。

// miso/include/miso/mhd_integrator_host.hpp
template <typename EOS, typename BoundaryCondition, typename Source>
void runge_kutta_4step(const Real dt, const EOS &eos,
                       const BoundaryCondition &bc, const Source &src,
                       Fields<Real, backend::Host> &qq) {
  update_sc4(dt / 4.0, eos, src, qq, qq, qq_rslt);
  qq_argm.copy_from(qq_rslt);
  apply_boundary_condition(bc, qq_argm);

  update_sc4(dt / 3.0, eos, src, qq, qq_argm, qq_rslt);
  qq_argm.copy_from(qq_rslt);
  apply_boundary_condition(bc, qq_argm);

  update_sc4(dt / 2.0, eos, src, qq, qq_argm, qq_rslt);
  qq_argm.copy_from(qq_rslt);
  apply_boundary_condition(bc, qq_argm);

  update_sc4(dt, eos, src, qq, qq_argm, qq_rslt);
  qq.copy_from(qq_rslt);
  apply_boundary_condition(bc, qq);
}

7.2 段の係数を確かめる

線形の方程式 \(dq/dt = \lambda q\) では、\(R(q) = \lambda q\) なので、\(h = \lambda\Delta t\) として順に代入すると

\[ q^{n+1} = \left(1 + h + \frac{h^2}{2} + \frac{h^3}{6} + \frac{h^4}{24}\right) q^n \]

となり、厳密解 \(e^{h} q^n\) の Taylor 展開と 4 次の項まで一致します。 次の短いプログラムは、\(dq/dt = -q\) を同じ 4 段で \(t = 1\) まで解き、厳密解 \(e^{-1}\) との差を表示します。

// rk4_linear.cpp: MISO と同じ 4 段の係数で dq/dt = -q を解く（説明用の例）
#include <cmath>
#include <iostream>

double solve(int n_step) {
  const double dt = 1.0 / n_step;
  double q = 1.0;                       // 時刻 t の値（MISO の qq）
  for (int n = 0; n < n_step; ++n) {
    double q_argm = q;                  // 右辺を評価する値（MISO の qq_argm）
    q_argm = q + dt / 4.0 * (-q_argm);  // 1 段目
    q_argm = q + dt / 3.0 * (-q_argm);  // 2 段目
    q_argm = q + dt / 2.0 * (-q_argm);  // 3 段目
    q = q + dt * (-q_argm);             // 4 段目で q を更新する
  }
  return q;
}

int main() {
  for (int n : {10, 20, 40}) {
    std::cout << "n_step = " << n
              << "  error = " << std::abs(solve(n) - std::exp(-1.0)) << "\n";
  }
}

コラム：この 4 段の方法と非線形の方程式

この形の多段法は、Jameson, Schmidt, Turkel (1981, AIAA Paper 81-1259) が圧縮性流体の計算に用いたことで知られています。 各段で保存する配列が少なくて済むのが利点です。

係数 \(1/4, 1/3, 1/2, 1\) は、線形の方程式に対して 4 次精度になるように選ばれています。 非線形の方程式 \(dq/dt = f(q)\) では、\(\Delta t^3\) の項のうち \(f''f^2\) に掛かる係数を展開して比べると、この方法では \(1/8\)、厳密解では \(1/6\) となり一致しません。 そのため、非線形の方程式に対する形式上の精度は 2 次です。 一方、線形の安定領域は古典的な 4 段 Runge–Kutta 法と同じです。 miso/include/miso/mhd_resistivity.hpp のコメントにある「RK4 の安定条件 \(\lambda\Delta t < 2.78\)」も、この安定領域から来ています。

8. 4 次中心差分と右辺の計算

8.1 space_centered_4th

空間微分は、4 次精度の中心差分で近似します。等間隔の格子で、

\[ \left.\frac{\partial f}{\partial x}\right|_i \approx \frac{-f_{i+2} + 8 f_{i+1} - 8 f_{i-1} + f_{i-2}}{12\, \Delta x} \]

です。誤差は \(\Delta x^4\) に比例します。片側に 2 点ずつ使うので、ゴーストセルの幅（grid.margin）は 2 以上必要です。

// miso/include/miso/mhd_integrator.hpp
template <typename Real>
__host__ __device__ inline Real
space_centered_4th(Array3DView<const Real> qq, Real dxyzi, int i, int j, int k,
                   int is, int js, int ks) {
  // clang-format off
  return (
    -     qq(i + 2*is, j + 2*js, k + 2*ks)
    + 8.0*qq(i +   is, j +   js, k +   ks)
    - 8.0*qq(i -   is, j -   js, k -   ks)
    +     qq(i - 2*is, j - 2*js, k - 2*ks)
  )*inv12<Real>*dxyzi;
  // clang-format on
};

9. 境界条件とハロー交換

9.1 apply_boundary_condition

RK4 の各段と人工粘性の各方向のあとで、次の関数が呼ばれます。

// miso/include/miso/mhd_integrator_host.hpp
template <typename BoundaryCondition>
void apply_boundary_condition(const BoundaryCondition &bc,
                              Fields<Real, backend::Host> &qq) {
  bc.apply(qq.view(), grid.const_view());
  halo_exchanger.apply(qq);
}

  1. bc.apply で、ユーザーが与えた物理境界条件を適用します。

  2. halo_exchanger.apply で、隣のランクとゴーストセルの値を交換します（ハロー交換、第 8 章）。

bc.apply の引数の形は、Model の bc が必ず持つ約束です。

void apply(mhd::FieldsView<Real> qq, GridView<const Real> grid) const;

9.2 ハロー交換と周期境界

ハロー交換は miso/include/miso/mhd_halo_exchange.hpp の HaloExchanger にあります。 CPU 版の apply は、\(x\) → \(y\) → \(z\) の順に、方向ごとに次を行います。

  1. 9 変数のうち送る範囲（端から margin 枚）を送信用の Array4D に詰めます。

  2. MPI_Isend と MPI_Irecv で正の側と負の側に同時に送受信し、MPI_Waitall で待ちます。

  3. 受け取った値をゴーストセルへ書き込みます。

方向を 1 つずつ交換するので、\(y\) 方向で送る範囲には、直前に \(x\) 方向で受け取ったゴーストセルも含まれます。 そのため、角のゴーストセルにも正しい値が入ります。

隣のランクは、mpi::Shape が MPI_Cart_shift で求めた x_procs_pos などです。 domain.periodic で周期境界にした方向では、領域の端のランクの隣が反対側の端のランクになります。 その方向のプロセス数が 1 なら、隣は自分自身です。 つまり、周期境界はハロー交換が担います。全方向が周期境界の問題では、bc に何もしない mhd::EmptyBoundaryCondition を使えます。

周期境界にしない方向の端では、隣が MPI_PROC_NULL になり、交換は行われません。そのゴーストセルを埋めるのが bc.apply の役目です。

9.3 物理境界の例

demo/hd2d_rayleigh_taylor/src/main.cpp の BoundaryCondition は、\(y\) 方向の両端に対称境界を置きます。

// demo/hd2d_rayleigh_taylor/src/main.cpp の BoundaryCondition::apply（抜粋）
namespace bc = miso::boundary_condition;
Backend btag{};

if (bc::is_physical_boundary(Direction::Y, Side::INNER, mpi_shape)) {
  bc::symmetric(btag, qq.ro, grid, Sign::Pos, Direction::Y, Side::INNER);
  bc::symmetric(btag, qq.vx, grid, Sign::Pos, Direction::Y, Side::INNER);
  bc::symmetric(btag, qq.vy, grid, Sign::Neg, Direction::Y, Side::INNER);
  ...
}

is_physical_boundary（miso/include/miso/boundary_condition.hpp）は、このランクの \(y\) 方向の負の側（Side::INNER）に隣のランクがない、つまり領域の端を受け持っているかを調べます。 MPI で分割していると、端を受け持たないランクもあるので、この判定が必要です。

symmetric は、境界をはさんで鏡に映した位置の値をゴーストセルに写します。Sign::Neg なら符号を反転します。 境界に垂直な速度 vy だけを反転させ、境界を通り抜ける流れを 0 にしています。

10. 人工粘性

中心差分だけでは、衝撃波などの急な変化の近くで数値振動が生じます。 MISO は、RK4 のあとに人工粘性（人工拡散）を 1 回かけて、急な変化の近くだけを選んでならします。 実装は miso/include/miso/mhd_artificial_viscosity_host.hpp の impl_host::ArtificialViscosity で、方法は Rempel (2014, ApJ 789, 132) に基づきます（config_defaults.hpp のコメント）。

10.1 方向ごとの更新

// miso/include/miso/mhd_integrator_host.hpp（抜粋）
template <typename EOS, typename BoundaryCondition>
void apply_artificial_viscosity(const Real dt, const EOS &eos,
                                const BoundaryCondition &bc,
                                Fields<Real, backend::Host> &qq) {
  artdiff.characteristic_velocity_eval(qq, eos);

  // x direction
  artdiff.update(qq, qq_rslt, Direction::X, dt);
  qq.copy_from(qq_rslt);
  apply_boundary_condition(bc, qq);

  ...  // y, z 方向も同じ 3 行（Direction::Y, Direction::Z）
}

最初に特性速度 \(c = f_{cs} c_s + f_{vv}|\boldsymbol{v}| + f_{ca} c_A\) を全格子点で求めます（係数は設定の mhd.artificial_viscosity.cs_fac など）。 そのあと \(x, y, z\) の順に 1 方向ずつ更新し、そのたびに境界条件とハロー交換を行います。

10.2 拡散流束

1 方向の更新は、セル境界 \(i+1/2\) での流束 \(F_{i+1/2}\) の差です。

\[ q_i^{\text{new}} = q_i - \frac{\Delta t}{\Delta x}\left(F_{i+1/2} - F_{i-1/2}\right) \]

対象は \(\rho\), \(\rho\boldsymbol{v}\), \(\boldsymbol{B}\), \(\phi\), \(\rho e\) です。流束は miso/include/miso/limiter.hpp の 2 つの関数で作ります。

関数

計算

dqq_eval(q_{i-1}, q_i, q_{i+1}, ep)

傾き \(\Delta q_i\)。\(\varepsilon(q_i - q_{i-1})\)、\(\varepsilon(q_{i+1} - q_i)\)、\((q_{i+1} - q_{i-1})/2\) の符号がそろっていれば絶対値が最小のもの、そろっていなければ 0（一般化 minmod 制限子）。\(\varepsilon\) は設定の ep

flux_core(q_i, q_{i+1}, Δq_i, Δq_{i+1}, c, fh)

セル境界の左右の値 \(q_L = q_i + \Delta q_i/2\), \(q_R = q_{i+1} - \Delta q_{i+1}/2\) を作り、\(F = -\frac{1}{2} c\, \Phi\, (q_R - q_L)\) を返す

\(\Phi\) は、\(r = \min\left(1, (q_R - q_L)/(q_{i+1} - q_i)\right)\) を使って、\(r \ge 0\) なら \(\max(0, 1 + h(r - 1))\)、\(r < 0\) なら 0 です。\(h\) は設定の fh です。 変化がなめらかなところでは \(q_R \approx q_L\) なので流束はほぼ 0 です。急な変化があって \(q_R - q_L\) が大きく残るところだけで拡散が働きます。

エネルギーは、\(\rho e\) の流束で全エネルギーを更新したあと、新しい運動エネルギーと磁気エネルギーを引いて内部エネルギーに戻します。 人工粘性で失われた運動エネルギーと磁気エネルギーは、内部エネルギーに移ります。

13. ソースを読んで確かめる練習

練習 1：1 ステップで境界条件が呼ばれる回数

demo/mhd2d_vortex の設定で 1 ステップ進めるとき、bc.apply が何回呼ばれるかを、miso/include/miso/mhd_integrator_host.hpp を読んで数えてください。 初期条件を作るときに呼ばれる回数と、1 ステップで MPI_Allreduce が呼ばれる回数も数えてください。

解答・解説

1 ステップで 7 回です。

  • runge_kutta_4step の 4 段で、それぞれ apply_boundary_condition を 1 回ずつ（4 回）。

  • apply_artificial_viscosity の \(x, y, z\) の各方向で 1 回ずつ（3 回）。

apply_boundary_condition は bc.apply のあとに halo_exchanger.apply を呼ぶので、ハロー交換も 1 ステップで 7 回です。 2 次元の計算でも、\(z\) 方向の人工粘性の呼び出しは省かれないので回数は同じです。

初期条件を作るときは、MHD::apply_initial_condition の最後で 1 回呼ばれます。

MPI_Allreduce は、Integrator::cfl で 1 回です。ソース項が dt_limit() を持つ場合は、ModelBase::update でもう 1 回呼ばれます。

回数は、apply の中で呼び出し回数を数える境界条件を bc に使い、update() を直接呼んでも確かめられます。 apply は const のメンバ関数なので、数える変数はメンバの外（たとえば main.cpp の外側の変数）に置きます。 この方法で数えると、初期条件で 1、1 ステップで 7、さらに 2 ステップで 14 になります。

練習 2：既定値の補完

demo/hd2d_rayleigh_taylor/config.yaml には mhd.cfl_number が書かれていません。 この計算で使われる CFL 数と人工粘性のパラメータ ep の値を、config_defaults.hpp と merge_yaml を読んで答えてください。 実際に使われた値を、計算後のどのファイルで確かめられるかも説明してください。

解答・解説

CFL 数は既定値の 0.5、ep はユーザーが書いた 2.0 です。

merge_yaml は既定値の mhd セクションに入り、cfl_number はユーザーの設定にないので 0.5 を足します。 artificial_viscosity はセクション（YAML の Map）なので再帰的に入り、キーごとに補います。 ep はユーザーが書いているので上書きしません。ユーザーが書いていない mhd.resistivity.cfl_number も 0.5 で補われます。

補った結果は、save_metadata() が出力先に書く data/config.yaml に残ります。 demo/hd2d_rayleigh_taylor の設定では io.save_dir が既定の data/ なので、demo/hd2d_rayleigh_taylor/data/config.yaml です。

練習 3：重力のソース項

demo/hd2d_rayleigh_taylor/src/main.cpp の SourceTerm は、\(-y\) 方向の一様な重力（大きさ \(g\)）を与えます。 このソース項を使うと、update_sc4 のどの式のどの項が変わるかを説明してください。 また、全エネルギーを保存させるには、ei のソース項として何を返す必要があるかを、8.3 節のエネルギーの式から説明してください。

解答・解説

SourceTerm が定義しているのは vx, vy, vz, ei で、0 以外を返すのは vy の \(-g\rho\) だけです。

// demo/hd2d_rayleigh_taylor/src/main.cpp
__host__ __device__ inline Real vy(mhd::FieldsView<const Real> qq, int i, int j,
                                   int k) const noexcept {
  return -g_grav * qq.ro(i, j, k);
}

変わるのは、\(y\) 方向の運動方程式の +source_vy(src, c_qq, i, j, k) の項です。

\[ \rho^{\text{rslt}} v_y^{\text{rslt}} = \rho^n v_y^n + \Delta t' \left[ \cdots - g\rho \right] \]

\(\rho\) は c_qq、つまりその段の qq_argm の値で、RK4 の 4 段のそれぞれで評価されます。 ro, bx, by, bz は定義されていないので、if constexpr で 0 になります。

エネルギーについて：MISO のエネルギーの式は全エネルギー \(E\) の式で、内部エネルギーは \(e = (E - \rho v^2/2 - B^2/8\pi)/\rho\) で戻します。 重力が流体にする仕事 \(\rho\boldsymbol{v}\cdot\boldsymbol{g} = -g\rho v_y\) を \(S_E\) に入れないと、重力で増えた運動エネルギーの分が \(E\) に足されないまま引かれ、内部エネルギーが減ります。 全エネルギーを保存させるには、ei で \(-g\rho v_y\) を返します。

// ei のソース項の例（説明用）
__host__ __device__ inline Real ei(mhd::FieldsView<const Real> qq, int i, int j,
                                   int k) const noexcept {
  return -g_grav * qq.ro(i, j, k) * qq.vy(i, j, k);
}

demo/hd2d_rayleigh_taylor の ei は 0 を返しているので、このデモでは、重力がした仕事の分が内部エネルギーの側で差し引かれます。

重力を足すときは、ソース項のほかに、初期条件を静水圧平衡にすること（このデモでは \(p = p_0 - g\rho y\)）と、\(y\) 方向の端の境界条件も考える必要があります。

練習 4：2 次元計算での z 方向の差分

demo/mhd2d_vortex は k_size: 1 の 2 次元計算です。 このとき、update_sc4 の \(z\) 方向の差分、CFL 条件、ハロー交換、人工粘性の \(z\) 方向の更新がどうなるかを、miso/include/miso/grid.hpp の AxisGrid を読んで説明してください。

解答・解説

AxisGrid は、格子数 size が 1 の方向で stride = 0、margin = 0、total = 1 とし、格子間隔 ds を 1.e30、その逆数 dsi を 0 にします。 grid.ks は stride なので 0、grid.k_margin は 0、grid.k_total は 1 です。

  • 差分：space_centered_4th(..., 0, 0, grid.ks) は ks = 0 なので 4 点がすべて同じ格子点 k になり、\((-1 + 8 - 8 + 1)\) の組み合わせで 0 になります。さらに dzi も 0 です。\(z\) 方向の微分の項は 0 になります。

  • CFL 条件：min3(dx[i], dy[j], dz[k]) で dz が 1.e30 なので、\(z\) 方向は時間刻みを制限しません。

  • ハロー交換：HaloExchanger の \(z\) 方向は grid.k_size > 1 が偽なので行いません（GPU 版は grid.k_total > 1 で判定します）。

  • 人工粘性：Direction::Z では ks = 0 なので左右の値がすべて同じになり、流束の差 \(F_{i+1/2} - F_{i-1/2}\) が 0 です。掛ける dzi も 0 なので値は変わりません。

ループの範囲はどれも k = 0 だけになり、配列の範囲外を読むことはありません。

練習 5：4 次中心差分の精度を確かめる（発展）

MISO を使うプログラムを自分で書き、mhd::space_centered_4th で \(f(x) = \sin x\) の微分を求めて、\(\cos x\) との差の最大値を調べてください。 \(0 \le x < 2\pi\) を \(n\) 個のセルに分け、セル中心 \(x_i = (i + 1/2)\Delta x\) に値を置きます。 \(n = 16, 32, 64\) で誤差がどう変わるかを確かめてください。 ビルドは、第 1 章 の「自分のプログラムから MISO を使う最小の CMake 設定」を使います。

解答・解説

作るものは次のとおりです。

  1. #include <miso/core.hpp> と #include <miso/mhd.hpp> を書きます（space_centered_4th は mhd.hpp から読み込まれます）。

  2. ゴーストセルを両側に 2 つずつ付けた Array3D<double>（大きさ n + 4, 1, 1）を作り、添字 i の位置 \(x = (i - 2 + 1/2)\Delta x\) に \(\sin x\) を入れます。ゴーストセルにも同じ式で値を入れると、周期境界と同じになります。

  3. i = 2 から n + 1 まで、mhd::space_centered_4th(f.const_view(), 1.0 / dx, i, 0, 0, 1, 0, 0) と \(\cos x\) の差の最大値を求めます。

space_centered_4th は MPI を使わないので、このプログラムでは Env を作らなくても動きます。

結果の例は次のとおりです。

n = 16  error = 0.000763339
n = 32  error = 4.90805e-05
n = 64  error = 3.08927e-06
ratio 16/32 = 15.5528
ratio 32/64 = 15.8874

格子数を 2 倍にすると誤差がおよそ \(1/16 = 1/2^4\) になり、4 次精度であることが分かります。 差分式の誤差の主要項は \(-\frac{\Delta x^4}{30} f^{(5)}\) で、\(f = \sin x\) では最大値が \(\Delta x^4/30\) です。\(n = 16\) では \(\Delta x = \pi/8\) なので \((\pi/8)^4/30 \approx 7.9\times 10^{-4}\) となり、結果と合います。

練習 6：出力の時刻

demo/mhd2d_vortex を dt_output: 0.01 で実行すると、data/time/time.00000001.txt の 1 行目は 0.0100069 のように、0.01 からわずかにずれた値になります。 このずれが生じる理由を、ModelBase::save_if_needed と ModelBase::run を読んで説明してください。

解答・解説

run() は 1 ステップ進めるたびに save_if_needed() を呼び、time.time >= dt_output * n_output が成り立った最初のステップで出力します。 時間刻み \(\Delta t\) は CFL 条件だけで決まり、出力時刻にちょうど届くように縮めることはしません。 そのため、出力されるのは 0.01 を初めて越えたステップの時刻で、0.01 より最大 \(\Delta t\) だけ後になります。

出力時刻の正確な値は、time/time.NNNNNNNN.txt の 1 行目に書かれています。解析で時刻を使うときは、dt_output の倍数ではなく、このファイルの値（pymiso が読む値）を使います。
